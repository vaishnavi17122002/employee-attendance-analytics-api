# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `punch_out` (~L510) | Called undefined function `compute_work_hours(punch_in, ts)`. | `POST /attendance/punch-out` raises `NameError: name 'compute_work_hours' is not defined`, returning `500 Internal Server Error`. | Replaced with defined helper `work_hours(punch_in, ts)`. |
| 2 | `punch_out` (~L511) | Called undefined function `compute_overtime(...)` and passed only 3 arguments instead of 4. | `POST /attendance/punch-out` raises `NameError: name 'compute_overtime' is not defined` (500 error). | Replaced with `overtime_minutes(ts, emp["shift_start"], emp["shift_end"], rec_day)`. |
| 3 | `punch_out` (~L508-515) | Failed to compute and persist `half_day` (Rule R5). | Punch-out records with `< 4.50` work hours had `half_day` remaining `False` or missing. | Added `half = bool(hours < 4.50)` and included `"half_day": half` in MongoDB `$set`. |
| 4 | `punch_out` (~L469-475) | Record looked up by `attendance_date(punch_out)` instead of employee's most recent `punch_in <= punched_at`. | Overnight shifts (e.g., 22:00–06:00) punching out past midnight/shift end returned 404 "attendance record not found". | Changed query to find latest record where `emp_code == body.emp_code` and `punch_in <= ts`, sorted by `punch_in DESC`. |
| 5 | `punch_out` (~L502-506) | Non-atomic punch out check allowed race conditions where simultaneous punch-outs could overwrite each other. | Concurrent punch-outs for same record both succeeded instead of exactly one returning 200 and second 409. | Added atomic filter condition `{"_id": record["_id"], "punch_out": None}` and checked `result.modified_count == 1`. |
| 6 | `punch_in` (~L440-459) | Relying on application-level read checks for duplicate punch-ins causes race conditions under concurrency. | Two parallel punch-in requests at the exact same millisecond could create duplicate records. | Leveraged unique index on `(emp_code, date)` and caught `DuplicateKeyError` to return `409 Conflict`. |
| 7 | `clean_attendance` (~L161-170) | Nested datetime instants inside `history[].at` and `history[].changes` were not normalized to epoch milliseconds. | `PATCH /attendance/...` response serialization threw TypeError or returned ISO strings instead of epoch ms ints. | Iterated through `history` array and converted `at`, `changes.punch_in.from/to`, `changes.punch_out.from/to` datetimes using `to_ms()`. |
| 8 | `ensure_indexes` (~L185-194) | Missing index for leaderboard range queries on `date` + `late_minutes`, causing COLLSCAN / inefficient scans. | Running `/admin/explain/late_leaderboard` failed index scan validation against 100k records. | Added compound index `[("date", ASCENDING), ("late_minutes", DESCENDING)]` and `[("department", ASCENDING), ("joined_on", ASCENDING)]`. |
| 9 | `department_summary_pipeline` (~L309-322) | Aggregating directly from `attendance_logs` dropped employees with zero attendance records from department headcount. | Departments with employees that had zero logs showed lower headcount than actual active employees (violating R9). | Aggregated from `employees` collection filtered by `joined_on <= month_end`, using `$lookup` with `preserveNullAndEmptyArrays: True`. |
| 10 | `leaderboard_pipeline` (~L357-374) | Naive index-based ranking assigned distinct ranks to tied employees or dropped ties at the cutoff. | Employees with equal total late minutes were assigned arbitrary ranks (1, 2, 3) instead of shared competition rank (1, 2, 2, 4). | Utilized MongoDB `$setWindowFields` with `$rank` output, sorted by `total_late_minutes DESC, emp_code ASC`, filtering `rank <= limit`. |
| 11 | `trend_pipeline` (~L377-404) | Days with zero attendance (e.g., weekends/holidays) were omitted from the daily series, corrupting moving average window. | Trend series had gaps in dates, and 7-day moving average skipped non-working days instead of spanning calendar window. | Added `$densify` stage across all calendar days in range and computed 7-day moving average with window `documents: [-6, 0]`. |

### Items examined and confirmed NOT to be defects:
- **`round_half_up` using `Decimal`:** Standard Python `round()` uses round-half-to-even (banker's rounding). Implementing rounding via `Decimal.quantize(..., rounding=ROUND_HALF_UP)` correctly adheres to rules R4 and R8.
- **Grace period calculation in `late_minutes`:** A punch-in exactly at 10 minutes (600 seconds) after `shift_start` is not late (`elapsed > 600`), and once strictly over 10 minutes, the full elapsed duration from `shift_start` is counted, which precisely follows rule R2.
